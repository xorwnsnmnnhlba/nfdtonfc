**포인트**: 구현 가능 여부와 기술 선택을 동시에 물어볼 때 **"의견만 부탁할게"** 로 명확히 범위 제한

---

### 구현 지시

## 3. CI/CD 구성 단계

### 작동 원리 먼저 이해
> "GitHub Actions에서 각 OS runner로 빌드한다면 어떻게 만들어지는거야?"

→ 이해 후

> "ㅇㅇ 대략적인 절차 다시 설명해주라"

→ 절차 확인 후

> "ㅇㅇ GitHub 연동은 했으니 이에 맞춰 workflow 파일 작성해주라"

**포인트**: 바로 구현 요청하지 않고 원리 → 절차 → 구현 순서로 단계적 진행

---

### 세부 조정
> "ㅇㅇ 그렇게 해야지.. windows나 WSL에서 실행 가능하도록 실행프로그램 만들어줘야지"  
> "nfdtonfc-linux가 아니라 nfdtonfc-ubuntu로 바꿔주라"  
> "아니 OS 최신버전을 모두 명확하게 표기해달라고 ㅎㅎㅎ"  
> "아니 돌려봤는데 제대로 동작 안하는데ㅠㅠ"

**포인트**: 작은 수정은 짧고 직접적으로. 오류 발생 시 로그 복붙

---

## 4. 오류 디버깅 단계

### 오류 로그 제공 패턴
> "이렇게 나오네  
> `chmod: gradlew: No such file or directory`"

> "이렇게 나오네  
> `Process completed with exit code 1`"

**포인트**: 오류 메시지를 그대로 복붙. 추가 설명 없이 로그만 줘도 충분

---

### 단계적 확인
> "빌드가 안되는데 흠.."  
→ 어느 단계 물어보면  
> "build (macos-latest...) Process completed with exit code 1."

**포인트**: 단계가 길 경우 먼저 어디서 실패했는지 물어봄 → 해당 로그만 제공

---

## 5. 기능 추가 단계

## 7. 플랫폼별 이슈 해결 단계

### 문제 현상 → 원인 추궁 패턴
> "env에 추가 안된것 같은데 흠.."  
> "windows에서 여전히 깨져나오고있어.. chcp 65001 넣어도ㅠㅠ 애당초 이 명령 없이도 한글 안깨지게 할수 있지 않을까?"  
> "아 여전히 이러네ㅠㅠㅠㅠ"  
> "아 또 안되네ㅠ"  
> "아니 그래도 안되네ㅠㅠ"

**포인트**: 안 된다는 것만 짧게 반복 전달. 로그/스크린샷 첨부로 보완

---

### 스크린샷으로 현상 설명
> (Finder에서 깨진 한글 파일명 스크린샷 첨부)  
> "이렇게 깨져나온다고"

**포인트**: 텍스트로 설명하기 어려운 현상은 스크린샷으로

---

### 원인 파악을 위한 단계적 확인 요청
> "실행파일 다운받아서 해봤는데 안된다고 ㅋㅋ"  
→ 어떤 OS, 어떤 오류 물어보면  
> "WSL 우분투에서 해봤는데 아무 반응이 없어 ㅋㅋㅋ"  
→ 명령어 실행 요청받으면  
> "exit code: 1로 나오네"  
→  
> "아무것도 안나와"

**포인트**: 진단 명령어를 하나씩 실행하며 결과 전달. 서두르지 않고 단계별로

---

### macOS 특이 현상 보고
> "아 그래도 이상하네"  
> "NFD로 나오네"  
> "nfc로 바꿔도 MacOS 단에서 nfd로 강제변환하는것 같은데 흠..."  
> "아니 아무것도 안나와"  
> "아니 그래도 안되네 하........."

**포인트**: 결과를 정확하게 전달 (출력 내용, 동작 여부). 감탄사로 심각도 전달 가능 ㅋㅋ

## 질의 패턴 요약

| 상황 | 효과적인 질의 방법 |
|------|-------------------|
| 기술 선택 | "A로 구현 가능한가? 의견만 부탁" → 선택지 받기 → "후자로 구현해주라" |
| 오류 발생 | 오류 로그 그대로 복붙 |
| 현상 설명 | 스크린샷 첨부 + "이렇게 나온다고" |
| 안 될 때 | "아 또 안되네ㅠ" + 실행 결과 전달 |
| 원리 이해 | "어떻게 만들어지는거야?" → 이해 후 구현 요청 |
| 스타일 지적 | 발견 즉시 짧게 ("중괄호 좀 넣어주라", "yield 안쓰고싶은데") |
| 리팩터링 | 방향만 제시 ("클래스 분해해주라", "객체지향 잘 살려서") |
| 추가 고려 | "~도 생각해봐야할듯한데" |
| 확인 | 짧은 명령어 실행 결과 하나씩 전달 |

---

## 핵심 교훈

1. **짧고 직접적으로** - 긴 설명 없이 핵심만 전달해도 충분
2. **단계적으로** - 한 번에 모든 걸 요청하지 않고 결과 보고 다음 단계로
3. **로그/스크린샷** - 텍스트 설명보다 실제 출력 결과가 훨씬 효과적
4. **의견 먼저** - 모르는 영역은 구현 전에 "의견만 부탁" 으로 방향 확인
5. **스타일 즉시 지적** - 마음에 안 드는 코드는 발견하자마자 바로 피드백
