CI vs CD

CI(지속적 통합) — 코드 변경마다 자동 빌드·검증

CD(지속적 배포) — 검증된 빌드를 자동으로 사용자에게 전달

③ 단계별 구현 · Step 1

Trigger — 언제 실행할 것인가

릴리즈 파이프라인은 버전 태그를 트리거로 삼는다

# 태그 push 시에만 실행 (v1.0.0, v2.3.1 …) on: push: tags: - 'v*' permissions: contents: write # ← Release 생성에 반드시 필요
⚠️ permissions 빠뜨리면
Resource not accessible by integration — GitHub Release 생성 단계에서 403 오류 발생. Workflow 레벨 또는 release Job 레벨에 선언.

태그에서 버전 추출

# v1.2.3 → 1.2.3 - name: Extract version id: version shell: bash run: | echo "VERSION=${GITHUB_REF_NAME#v}" \ >> $GITHUB_OUTPUT # 이후 단계에서 참조 ${{ steps.version.outputs.VERSION }}
💡 버전을 build.gradle에 하드코딩하지 말 것
Gradle -Pversion= 플래그로 주입하면 소스 코드 수정 없이 버전 관리 가능. ./gradlew jpackageInstaller -Pversion=1.2.3
③ 단계별 구현 · Step 2

Matrix — 3개 OS를 단 한 번에

반복되는 Job 대신 strategy.matrix로 조합 폭발을 활용

jobs: build: strategy: matrix: include: - os: macos-15 ext: pkg os-name: macos - os: windows-2025 ext: msi os-name: windows - os: ubuntu-24.04 ext: deb os-name: ubuntu runs-on: ${{ matrix.os }} steps: - name: Build installer run: | ./gradlew jpackageInstaller \ -Pversion=${{ steps.version.outputs.VERSION }}
🍎macOS 15pkg

dmg는 postinstall 스크립트 미지원 → PATH 등록 불가. 반드시 pkg 타입 사용.

🪟Windows 2025msi

CLI 앱은 --win-console 옵션 필수. 없으면 “failed to launch JVM” 오류.

🐧Ubuntu 24.04deb

postinst 스크립트로 /usr/local/bin에 symlink 생성.

⚠️ latest 사용 금지 — ubuntu-latest는 버전이 교체되면 빌드 깨짐. 항상 ubuntu-24.04처럼 명시.
③ 단계별 구현 · Step 3

빌드 환경 준비

Java 셋업부터 jpackage 호출까지 — 함정이 2개 있다

Workflow Steps 순서

1
actions/checkout@v6
2
actions/setup-java@v5 (Zulu 25)
3
chmod +x gradlew (Unix only)
4
./gradlew jpackageInstaller -Pversion=…
5
actions/upload-artifact

🔥 함정 1 — Gradle Wrapper가 없다

Spring Initializr 기본 .gitignore에 gradlew, gradle/이 포함되어 있음 → CI에서 No such file or directory

./gradlew: No such file or directory

해결: .gitignore에서 Gradle Wrapper 항목 제거 후 커밋

🔥 함정 2 — jpackage 경로 하드코딩

// 나쁜 예 def jpackage = '/Library/Java/.../jpackage' // 좋은 예 def javaHome = System.getenv('JAVA_HOME') def jpackage = "${javaHome}/bin/jpackage"

로컬 경로는 CI 환경에 존재하지 않음

③ 단계별 구현 · Step 4

플랫폼별 PATH 자동 등록

jpackage 기본 설치로는 PATH에 아무것도 추가하지 않는다

🍎macOS · pkg

src/jpackage/postinstall 스크립트 → --resource-dir로 포함

#!/bin/bash ln -sf \ /Applications/nfdtonfc.app\ /Contents/MacOS/nfdtonfc \ /usr/local/bin/nfdtonfc
dmg 타입은 이 스크립트를 지원하지 않아 pkg 필수

🪟Windows · msi

MSI 데이터베이스에 직접 패치 (COM 자동화)

# patch-msi-path.ps1 # Environment 테이블 생성 # PATH 항목 삽입 # WriteEnvironmentStrings # → InstallExecuteSequence & src\windows\patch-msi-path.ps1 \ -MsiPath $msiPath
PowerShell 인라인 YAML 작성 시 백틱 충돌 → 반드시 .ps1 파일로 분리

🐧Ubuntu · deb

postinst / postrm 스크립트로 symlink 관리

# postinst ln -sf \ /opt/nfdtonfc/bin/nfdtonfc \ /usr/local/bin/nfdtonfc mandb -q # postrm rm -f /usr/local/bin/nfdtonfc
man 페이지는 postinst에 heredoc으로 직접 임베드 (별도 파일은 jpackage 경로 문제 발생)
③ 단계별 구현 · Step 5

아티팩트 수집 & Release 자동 생성

3개 Job의 결과물을 한 곳에 모아 GitHub Release에 붙인다

build job — 아티팩트 업로드

# 각 OS에서 결과물 이름 통일 - name: Rename artifact run: | cp build/jpackage/nfdtonfc-${VERSION}.pkg \ nfdtonfc-v1.0.0-macos.pkg - uses: actions/upload-artifact@v7 with: name: nfdtonfc-v1.0.0-macos.pkg path: nfdtonfc-v1.0.0-macos.pkg
💡 아티팩트 이름 규칙을 통일하라
nfdtonfc-{tag}-{os-name}.{ext} 형태로 고정하면 release job에서 artifacts/**/* 글로브 하나로 모두 처리 가능.

release job — Release 생성

release: needs: build # build 완료 후 실행 runs-on: ubuntu-24.04 steps: - uses: actions/download-artifact@v8 with: path: artifacts # 3개 OS 결과물 모두 - uses: softprops/action-gh-release@v3 with: files: artifacts/**/* env: GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
⚠️ needs: build 빠뜨리면 release job이 build와 동시에 실행되어 아티팩트가 없는 상태에서 Release 생성 시도 → 빈 릴리즈가 만들어짐
④ 실전 함정

Windows 한글이 ????로 나온다

cmd/PowerShell 기본 코드페이지(CP949) — 단순한 방법은 모두 효과가 없다

❌ 효과 없는 시도들

System.setOut(new PrintStream(System.out, true, UTF_8))

JVM 내부 스트림만 바꿔도 콘솔 코드페이지는 그대로

Runtime.getRuntime().exec("chcp 65001")

자식 프로세스에서 실행 → 현재 JVM 프로세스에 영향 없음

✅ Java 25 FFM API로 kernel32 직접 호출

Linker linker = Linker.nativeLinker(); SymbolLookup kernel32 = SymbolLookup .libraryLookup("kernel32", Arena.global()); MethodHandle setCP = linker.downcallHandle( kernel32.find("SetConsoleOutputCP").get(), FunctionDescriptor.of( ValueLayout.JAVA_INT, ValueLayout.JAVA_INT)); setCP.invoke(65001); // UTF-8
💡 FFM(Foreign Function & Memory) API
Java 22부터 정식 도입. JNI 없이 네이티브 함수를 직접 호출. jpackage JVM 옵션에 --enable-native-access=ALL-UNNAMED 필수.
④ 실전 함정 — 핵심

macOS APFS가 rename을 무시한다

nfdtonfc의 핵심 기능 구현에서 만난 4단계 연쇄 함정

1 Files.move()가 경로를 NFD로 변환

macOS VFS 레이어를 통과하면 NFC 경로가 NFD로 바뀜

→ FFM으로 rename() syscall 직접 호출
SymbolLookup.libraryLookup("libSystem.B.dylib", ...)
2 APFS: NFD→NFC rename이 no-op

APFS는 NFD와 NFC를 같은 파일로 인식 → 이름 변경 무시

→ 2단계 rename으로 우회
rename(src, tmp) // NFD → ASCII
rename(tmp, nfc) // ASCII → NFC
3 Path.toString()이 다시 NFD로 변환

macOS Path 구현이 내부적으로 NFD 변환

// 나쁜 예: target.toString()
// 좋은 예: 문자열 직접 조립
(parentStr + nfcName).getBytes(UTF_8)
4 pkg JRE가 파일명을 NFC로 반환

Files.walk() 결과가 NFC → 변환 필요 없다고 오판하여 skip

→ 문자열 비교 대신 바이트 비교
byte[] nfc = name.getBytes(UTF_8);
byte[] nfd = NFD(name).getBytes(UTF_8);
Arrays.equals(nfc, nfd)
완성

완성된 Workflow 한눈에

YAML 한 파일이 3개 OS 빌드·배포를 모두 처리한다 — build / release 두 Job 구조

name: Release on: { push: { tags: ['v*'] } } permissions: { contents: write } jobs: build: strategy: matrix: include: - os: macos-15 ext: pkg os-name: macos - os: windows-2025 ext: msi os-name: windows - os: ubuntu-24.04 ext: deb os-name: ubuntu runs-on: ${{ matrix.os }} steps: - uses: actions/checkout@v6 - id: version run: echo "VERSION=${GITHUB_REF_NAME#v}" >> $GITHUB_OUTPUT - uses: actions/setup-java@v5 with: { java-version: '25', distribution: 'zulu' } - name: Build installer run: ./gradlew jpackageInstaller -Pversion=… - name: Patch MSI PATH if: runner.os == 'Windows' run: src\windows\patch-msi-path.ps1 … - uses: actions/upload-artifact@v7 with: { name: nfdtonfc-…, path: nfdtonfc-… }
release: needs: build # build 완료 후 실행 runs-on: ubuntu-24.04 steps: - uses: actions/download-artifact@v8 with: { path: artifacts } - uses: softprops/action-gh-release@v3 with: { files: artifacts/**/* } env: GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} # download-artifact가 3개 OS 결과물을 # artifacts/ 폴더 하나로 모으고 # action-gh-release가 글로브 패턴으로 # 한 번에 Release에 첨부한다
